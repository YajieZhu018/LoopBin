# LoopBin Python environment, managed with uv instead of conda.
#
# Covers the model/training stack (pretrain/train/cluster/merge/calculateg/nmi) AND
# the process stage (loops+mcool+bedgraphs -> npy, needs cooler). All versions below
# were installed and verified working together on Python 3.9 via uv on this cluster:
# TensorFlow imports + forward pass, sklearn GaussianMixture, and cooler opening a
# real project .mcool at /resolutions/8000 and reading a submatrix all tested.
#
# cooler is pinned to 0.9.3 deliberately, not latest -- the current PyPI release
# (0.10.4) declares much stricter numpy/pandas/scipy requirements and silently
# upgrades numpy 1.19.5 -> 2.0.2 (breaking tensorflow==2.5.0 import) if installed
# unpinned. 0.9.3's own requirements (numpy>=1.9, pandas>1.0, scipy>=0.16) are loose
# enough to coexist with the pins below -- same version already used in loopbin.yml's
# conda env, so both env files now agree on it. pysam/pypairix are only under
# cooler's [complete] extra, not needed for the base cooler.Cooler(...) read path this
# package actually uses, despite earlier speculation in this file to the contrary.
#
# NOT yet covered: preprocess (bigwig -> bedgraph) needs the bigWigAverageOverBed
# binary specifically, which has no PyPI wheel at all -- only a bioconda package
# (see loopbin.yml) or a manual download from UCSC's kent-tools distribution
# (https://hgdownload.soe.ucsc.edu/admin/exe/) placed on PATH. Use the conda env for
# preprocess unless you set that up separately.
#
# To recreate:
#   module load uv
#   uv venv --python 3.9 .venv
#   source .venv/bin/activate
#   uv pip install -r requirements.txt
#
# Note: tensorflow==2.5.0 pulls in protobuf==6.x by default via uv's resolver,
# which breaks tensorflow's own generated _pb2.py files at import time
# ("Descriptors cannot be created directly..."). protobuf is pinned to 3.20.3
# below to avoid this — do not let it float.
